## Приоритет 1

### 1. Замена по всем файлам + опции поиска (M) — **СДЕЛАНО**

Реализовано: `src/shared/searchQuery.ts` (опции и построение матчера — общие
для main и превью в UI), `searchInWorkspaces(query, options)`,
`src/main/replaceInFiles.ts` (замена + один шаг Undo, снапшот в памяти),
панель Replace в `GlobalSearch.tsx`, `Cmd+Shift+R`. Замена в «грязных»
вкладках запрещена и подписана. Ниже — исходная постановка.


Поиск сейчас — подстрока без регистра, без regex, без замены. Это первое, обо что
спотыкается любой, кто пришёл из VS Code или IDEA: найти-то он нашёл, а
переименовать по проекту нечем, и человек уходит в терминал за `sed`.

Ложится в `searchInWorkspaces` (добавить режим regex/case/whole-word и маску
`**/*.ts`) и в `GlobalSearch.tsx` (панель Replace, предпросмотр «было → стало»,
чекбоксы по файлам). Обязательная часть — отмена: применять через ту же запись
в локальную историю (п. 2), иначе массовая замена становится необратимой.

Риск: замена в файле, открытом во вкладке с несохранёнными правками. Решение —
запрещать замену в грязных вкладках и говорить об этом явно.

### 2. Локальная история файла (M) — **СДЕЛАНО**

Реализовано: `src/main/localHistory.ts` (снапшоты в
`userData/localHistory/<хеш пути>/`, дедуп по sha1, склейка правок в пределах
2 минут, ретенция 14 дней / 50 версий / 8 МБ на файл, чистка при старте),
`LocalHistoryModal.tsx` (список версий + `DiffEditor` против текущего буфера)
из контекстного меню вкладки. Версию восстанавливаем в редактор одной
undo-операцией — на диск её уносит обычный автосейв, поэтому кодировка файла
сохраняется. Замена по проекту пишет версию в историю всегда, независимо от
склейки. Ниже — исходная постановка.


Автосейв пишет на диск через ~1.2 с после последнего нажатия, а вся защита от
«испортил и не помню, как было» — undo-стек Monaco, который умирает вместе с
вкладкой и не переживает reload. Для редактора, который сам сохраняет за тебя,
это дыра в характере продукта: он берёт на себя запись, но не берёт на себя
откат.

Снапшоты в `userData/localHistory/<хеш пути>/<timestamp>` (только при реальном
изменении, дедупликация по хешу содержимого, ретенция — N дней и M МБ на файл).
Показывать тем же `DiffEditor`, что уже стоит в git-панели, из контекстного меню
вкладки: «Локальная история». Это же закрывает §8 из `docs/BUGS.md` (внешняя
правка файла, который приложение только что сохранило) и делает безопасной
замену по проекту.

Дёшево по коду, дорого по продуманности: политика хранения и очистка.

### 3. Git: diff коммита и история файла (S/M)

В панели уже есть лог, но клик по коммиту копирует хеш — и всё
(`GitPanel.tsx:234`). Разворачивать коммит в список файлов и открывать diff можно
почти без новой инфраструктуры: `git show --stat` + `getDiff`, отрисовка — тем же
`DiffEditor`. Плюс «История этого файла» из контекстного меню дерева/вкладки
(`git log --follow -p`).

Отдача очень высокая: сейчас за «что было в этом коммите» надо уходить из
приложения, хотя ровно все кирпичи уже лежат.

### 4. Палитра команд (S)

Фич стало много: диктовка, перевод, чтение вслух, HTTP, work together, git,
терминал, превью, форматирование. Единственные входы — нативное меню и хоткеи,
которые надо помнить. `useMenuActions` уже держит реестр `MenuAction` → палитра
это список поверх него плюс fuzzy-фильтр (тот же, что в quick open).

Хоткей: `Cmd+Shift+A` (привычка IDEA — Find Action); `Cmd+Shift+P` занят под
Toggle Preview, и это правильно оставить как есть.

Побочный эффект: каждая новая фича становится обнаружимой без правки меню.

### 5. HTTP: окружения и сохранение запроса в файл (M)

`.http` уже понимает `@variables`, но одного и того же файла на dev/stage/prod не
получится: переменные лежат внутри файла, а секреты вместе с ним уезжают в git.
Формат JetBrains — `http-client.env.json` рядом с файлом плюс
`http-client.private.env.json` в `.gitignore` — знакомый, совместимый и решает
обе задачи. В UI — селектор окружения в тулбаре вкладки запроса.

Вторая половина: из формы HTTP Client сейчас можно скопировать curl, но нельзя
сохранить запрос в `.http`-файл. Кнопка «Сохранить как .http» превращает разовый
эксперимент в файл, который живёт в репозитории рядом с кодом — это ровно то,
ради чего в README написано «они plain text и лежат в git».

## Приоритет 2

6. **Compare With… (S).** Выделить два файла в дереве → diff. `DiffEditor` уже
   подключён, нужен только пункт меню и режим вкладки.
7. **Copy Path / Copy Relative Path / Open in Default App (S).** Контекстное меню
   дерева и вкладки. Ежедневная привычка из IDEA, стоит полчаса.
8. **Настройки редактора (S).** Размер и семейство шрифта, перенос строк,
   миникарта, размер табов, «убирать пробелы в конце строк при сохранении».
   Сейчас всё захардкожено в `App.tsx`; для «лёгкого редактора» это самые
   ожидаемые ручки, и они уже почти есть — есть `density`.
9. **Структура файла и `#символ` в quick open (M).** Без LSP: заголовки Markdown,
   плюс regex-извлечение функций/классов для JS/TS/Python (диагностика для них
   уже есть). Туда же `:номер строки` в quick open — дёшево и постоянно нужно.
10. **Git: создать ветку, fetch, stash, remote-ветки (M).** Сейчас
    `getBranches` читает только локальные `refs/heads`, а создать ветку изнутри
    приложения нельзя — за этим уходят в терминал.
11. **Open Recent — недавние проекты (S/M).** Воркспейсы сейчас один общий
    список; переключения между проектами нет. Для файлов такое уже есть
    (`recentExternalFiles.ts`) — тот же приём для папок.
12. **Разделение области редактора на две (L).** Две колонки (не произвольная
    сетка) — сравнить два файла, держать тест рядом с кодом. Дорого: вся
    вкладочная модель в `useTabs` про один активный файл.

## Приоритет 3 и спорное

13. **Офлайн-проверка орфографии (M/L).** У приложения сильная текстовая линия —
    диктовка, чтение вслух, перевод — и всё on-device. Орфография её замыкает и
    остаётся в том же обещании: словари качаются один раз, ничего не уходит
    наружу. Встроенный чекер Electron не подходит (Monaco рисует текст сам) —
    нужен свой воркер плюс декорации Monaco; инфраструктура воркеров и кеша
    моделей уже есть.
14. **LLM-помощник со своим ключом (M).** Формально против «no accounts, no
    telemetry», поэтому только как расширение по образцу Google Tasks:
    выключено по умолчанию, ключ свой, явное предупреждение, что текст уходит
    наружу. Самый уместный первый сценарий — сообщение коммита из готового
    diff: git-панель уже держит этот diff в руках.
15. **Второе окно (L). — СДЕЛАНО** (как «вытащить вкладку», а не как полный
    второй редактор). `mainWindowRef` заменён на primary + реестр окон;
    ptys принадлежат окну-владельцу, work-together — окну сессии. Вытащенное
    окно показывает только вкладку и редактор; сессия сохраняется лишь
    главным окном. Возврат — тем же жестом/пунктом меню.
16. **По мелочи:** scratch-файлы (быстрая заметка без выбора места), панель
    TODO/FIXME по проекту (обход дерева уже написан),
    ~~вставка картинки из буфера в Markdown с сохранением файла рядом~~
    (**сделано**: `src/main/pastedImages.ts` — файл в `assets/` рядом с
    документом, относительная ссылка в тексте, превью подставляет data-URL,
    потому что CSP не пускает `file:`), экспорт превью в HTML/PDF.

## Чего делать не стоит

- **Плагины и полноценный LSP** — это уже VS Code, и обещание «ничего не
  настраивать» умрёт первым.
- **Отладчик.**
- **Cookie jar в HTTP-клиенте** — отсутствие фонового состояния зафиксировано в
  README как свойство, а не недоработка.
