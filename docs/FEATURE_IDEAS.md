# Идеи фич

Анализ от 11.08.2026 (после v1.43.0), пересобран 29.08.2026 — палитра команд и
навигация по структуре файла сделаны и убраны отсюда. Здесь только то,
чего в приложении **нет**: сделанное отсюда удаляется — оно описано в
[README.md](../README.md) и покрыто кейсами в [TEST_CASES.md](TEST_CASES.md).
У каждого пункта указано, куда он ложится и сколько стоит: S — вечер,
M — день-два, L — неделя и больше.

## Приоритет 1

### 1. Git: diff коммита и история файла (S/M)

В панели уже есть лог, но клик по коммиту копирует хеш — и всё
(`GitPanel.tsx:234`). Разворачивать коммит в список файлов и открывать diff можно
почти без новой инфраструктуры: `git show --stat` + `getDiff`, отрисовка — тем же
`DiffEditor`. Плюс «История этого файла» из контекстного меню дерева/вкладки
(`git log --follow -p`).

Отдача очень высокая: сейчас за «что было в этом коммите» надо уходить из
приложения, хотя ровно все кирпичи уже лежат.

## Приоритет 2

2. **Compare With… (S).** Выделить два файла в дереве → diff. `DiffEditor` уже
   подключён, нужен только пункт меню и режим вкладки.
3. **Настройки редактора (S).** Размер и семейство шрифта, перенос строк,
   миникарта, размер табов, «убирать пробелы в конце строк при сохранении».
   Сейчас всё захардкожено в `App.tsx`; для «лёгкого редактора» это самые
   ожидаемые ручки, и они уже почти есть — есть `density`.
4. **Git: создать ветку, fetch, stash, remote-ветки (M).** Сейчас
   `getBranches` читает только локальные `refs/heads`, а создать ветку изнутри
   приложения нельзя — за этим уходят в терминал.
5. **Open Recent — недавние проекты (S/M).** Воркспейсы сейчас один общий
   список; переключения между проектами нет. Для файлов такое уже есть
   (`recentExternalFiles.ts`) — тот же приём для папок.
6. **Разделение области редактора на две (L).** Две колонки (не произвольная
   сетка) — сравнить два файла, держать тест рядом с кодом. Дорого: вся
   вкладочная модель в `useTabs` про один активный файл.

## Приоритет 3 и спорное

7. **LLM-помощник со своим ключом (M).** Формально против «no accounts, no
   telemetry», поэтому только как расширение по образцу Google Tasks:
   выключено по умолчанию, ключ свой, явное предупреждение, что текст уходит
   наружу. Самый уместный первый сценарий — сообщение коммита из готового
   diff: git-панель уже держит этот diff в руках.
8. **Символы по всему проекту (M).** `lib/symbols.ts` уже умеет доставать
   структуру одного файла; тот же разбор по всем файлам воркспейса (с кэшем по
   mtime) даёт «найти класс/функцию по имени» без LSP — это IDEA-шный
   `Cmd+Alt+O`, и в палитре/quick open для него уже есть место.
9. **Структура для Java/Kotlin и Go (S).** Сейчас разбор знает md, js/ts и
   python. Языки с явными объявлениями ложатся в тот же построчный подход, но
   у Java выше цена ошибки (модификаторы, дженерики, аннотации) — стоит делать
   только с набором примеров под рукой.
10. **Панель структуры сбоку (S/M).** Тот же `extractSymbols`, но постоянным
    списком в сайдбаре с подсветкой текущей позиции — для длинного markdown
    это заметно удобнее, чем каждый раз открывать `#`.
11. **По мелочи:** scratch-файлы (быстрая заметка без выбора места), панель
    TODO/FIXME по проекту (обход дерева уже написан), экспорт превью в
    HTML/PDF.

## Чего делать не стоит

- **Плагины и полноценный LSP** — это уже VS Code, и обещание «ничего не
  настраивать» умрёт первым.
- **Отладчик.**
- **Cookie jar в HTTP-клиенте** — отсутствие фонового состояния зафиксировано в
  README как свойство, а не недоработка.

## Правило для новых файловых фич

Доступ к файловой системе берётся из `src/main/pathAccess.ts` — main действует
только на пути внутри открытых воркспейсов, своего `userData` и того, что сам
выдал (файл из ОС, drag&drop, листинг quick open, буфер обмена Finder, список
недавних внешних). Новая фича берёт доступ оттуда же, а не расширяет поверхность
мимо него.
