# Рефакторинг: что стоит сделать

Снимок на 2026-07-09, после добавления вкладок/настроек/плотности интерфейса.
Ничего из этого не сломано и не критично — это скорее список "пока не разрослось
ещё больше", отсортированный по пользе/затратам.

## 1. `App.tsx` стал god-component (842 строки)

Один файл сейчас отвечает за: дерево воркспейсов, вкладки/файлы, терминалы,
контекстное меню, rename/create-диалоги, clipboard дерева, drag&drop reveal,
настройки, тему, markdown preview, все горячие клавиши, autosave, отслеживание
внешних изменений файла. Из-за этого сложно быстро понять, что где лежит, и
любое изменение рискует задеть несвязанную логику.

**Предложение** — разбить на кастомные хуки, каждый со своим стейтом и эффектами:

- `useTabs()` — `tabs`/`activeTabPath`, open/close/save/reload/remapTabPaths
- `useSettings()` — загрузка/сохранение/апдейт `AppSettings`
- `useTheme()` — `isDark` + подписка на OS-тему
- `useWorkspaceTree()` — `rootNodes`, add/remove/rename/move/copy/delete,
  `revealPath`
- `useTerminals()` — `terminals`/`activeTermId`, open/close

`App.tsx` тогда становится в основном JSX + подключение хуков — заметно легче
читать и тестировать по отдельности.

## 2. `AppSettings` продублирован в 4 местах

`src/main/index.ts`, `src/preload/index.ts`, `src/preload/index.d.ts` и
`src/renderer/src/App.tsx` — у каждого своя копия одного и того же интерфейса
(`tabsEnabled`, `autosaveEnabled`, `uiMode`). При добавлении `large`-режима
пришлось руками поправить 4 файла — уже проявившийся риск рассинхронизации.

**Предложение** — вынести `AppSettings` (тип + `DEFAULT_SETTINGS`) в один
файл, например `src/shared/settings.ts`, без Node/DOM-специфичных импортов, и
импортировать его из main, preload и renderer. Три отдельных tsconfig
(`node`/`web`) не мешают такому файлу, если он не тянет платформенные типы.

## 3. Дублирование/устаревание `isIgnored`

- `src/main/index.ts:67` — основная реализация, плюс `.gitignore` через пакет
  `ignore`.
- `src/renderer/src/components/FileSearch.tsx:21` — своя копия с укороченным
  списком, без `.gitignore`.

Но деревья (`rootNodes`), которые приходят из main в `FileSearch`, уже
отфильтрованы на сервере — значит проверка в `FileSearch` сейчас **мёртвый
код** (отфильтровывать нечего, всё нужное уже вырезано раньше). Либо удалить
её как бесполезную, либо, если задумывалась доп. защита — свести к единому
источнику правды через shared-модуль.

## 4. Main-процесс — один файл на 609 строк

`src/main/index.ts` совмещает: работу с воркспейсами, `.gitignore`,
построение дерева файлов, полнотекстовый поиск, file watcher (self-write
трекинг), IPC для файлов/настроек/темы, PTY/терминалы, сборку меню окна.

**Предложение** — разнести по модулям с сохранением `index.ts` как точки
входа, которая их подключает:

- `main/workspaces.ts` — дерево, `.gitignore`, поиск
- `main/watcher.ts` — `fs.watch`, self-write трекинг, debounce
- `main/settings.ts` — load/save настроек
- `main/terminals.ts` — PTY-хендлеры
- `main/menu.ts` — `buildAppMenu`

## 5. Типизация `any` вместо конкретных типов

- Renderer: `editorRef = useRef<any>(null)`, `handleEditorDidMount = (editor: any) => ...`
  — можно взять реальный тип из `monaco-editor` (`monaco.editor.IStandaloneCodeEditor`).
- Main: 13 мест с `any` (в основном `buildFileTree`, IPC-параметры без явного типа).
  Стоит завести общий `FileNode`-тип (сейчас он есть только в
  `FileTree.tsx`) и типизировать построение дерева и IPC-контракты им же —
  через тот же `src/shared/` из пункта 2.

## 6. Повторяющаяся разметка тулбара и модалок

- Кнопки тулбара (Search/Add Folder/Save/Terminal/Settings и т.п.) почти
  дословно повторяют один и тот же набор классов — можно вынести в
  `ToolbarButton`.
- Rename/Create/Settings-модалки повторяют одну и ту же обёртку
  (`fixed inset-0 ... bg-black/40` + `onClick={stopPropagation}` на карточке,
  включая `Escape`-обработку, реализованную по-разному в разных местах).
  Общий `<Modal>` уберёт дублирование и сделает поведение (Escape, клик вне)
  единообразным везде, а не только там, где его явно прописали.

## 7. Хардкод hex-цветов терминала

В `App.tsx` четыре раза встречаются одни и те же hex (`#1e1e1e`, `#252525`,
`#323232`, `#2d2d2d`, плюс `#181818` в `Terminal.tsx`) — сознательно
зафиксированная тёмная палитра терминала, не зависящая от темы приложения.
Стоит вынести в именованные CSS-переменные (по аналогии с `--fleet-*`, но без
переключения по теме), чтобы не искать/менять hex по всему файлу вручную.

## 8. `window.confirm` / `alert` для всех подтверждений и ошибок

8 мест в `App.tsx` (удаление файла, закрытие несохранённой вкладки, ошибки
create/rename/move/copy) используют нативные браузерные диалоги — резко
выбиваются на фоне остального кастомного UI (особенно с кастомным
тайтлбаром). Стоит завести один `<ConfirmDialog>`/`<AlertDialog>` в стиле
уже существующих rename/create-модалок.

## 9. Незакрытый lint-warning в `FileTree.tsx`

`react-hooks/set-state-in-effect` на эффекте авто-раскрытия папки (вызов
`setExpanded` синхронно внутри `useEffect`). Функционально безвреден (не
зациклится), но стоит переписать через вычисляемое значение вместо
стейта, раз уж лишний раз задевали этот файл несколько раз за сессию.

## 11. Не прогнан `npm run format`

В проекте сотни pretty-warning'ов (точки с запятой, кавычки) вперемешку —
почти во всех тронутых за сессию файлах. Разовый прогон
`npm run format` (уже есть в `package.json`) причесал бы это без риска
(prettier не меняет логику), сделав будущие диффы чище.

---

### Рекомендованный порядок

1. Вынести `AppSettings`/`FileNode` в shared-модуль (пункты 2, 5) — небольшая
   правка, сразу убирает реальный риск рассинхронизации.
2. Разбить `App.tsx` на хуки (пункт 1) — самое трудоёмкое, но самое полезное
   для дальнейшей поддержки.
3. Разнести `main/index.ts` по модулям (пункт 4).
4. `<Modal>`/`<ConfirmDialog>`/`ToolbarButton` (пункты 6, 8) — полировка,
   можно делать по ходу следующих фич.
5. `npm run format` (пункт 11) — в любой удобный момент, отдельным коммитом.
