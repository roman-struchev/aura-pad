# AuraPad — аудит кода, баги и оптимизации

Дата аудита: 2026-07-10. Проанализированы `src/main`, `src/preload`, `src/renderer`, конфиги сборки и содержимое готовой mac-сборки (`dist/mac-arm64`).

**Статус: все пункты ниже (кроме раздела 4) исправлены в v1.2.0.** Раздел 4 (Windows-пути) сознательно не применён — см. пометку в начале раздела.

---

## 1. Критичные баги — ✅ исправлены

### 1.1. Повторная регистрация IPC-хендлера `create-pty` при пересоздании окна (macOS)
`src/main/index.ts:130` вызывал `registerCreatePtyHandler(mainWindow)` внутри `createWindow()`. На macOS после закрытия окна приложение живёт дальше; клик по иконке в доке → `activate` → `createWindow()` → **вторая** регистрация хендлера, привязанная к уже разрушенному окну — терминалы переставали работать после переоткрытия окна.

**Исправлено:** хендлер регистрируется один раз в `app.whenReady()`, окно резолвится динамически через `mainWindowRef`.

### 1.2. После пересоздания окна на macOS переставали работать вотчеры
На `window-all-closed` вызывались `killAllPtys()`/`closeAllWatchers()`, но при `activate` `setupWatchers()` не вызывался заново.

**Исправлено:** `setupWatchers()` теперь вызывается и в `activate`.

### 1.3. Потеря несохранённых изменений при закрытии окна/приложения
Не было проверки на несохранённые вкладки при закрытии.

**Исправлено:** `close` в main перехватывается, renderer спрашивают через IPC (`request-close`/`confirm-close`), показывается подтверждение при наличии несохранённых вкладок.

### 1.4. Клик по ссылке в Markdown-превью уводил всё приложение на внешний сайт
Обрабатывался только `setWindowOpenHandler`, не `will-navigate`.

**Исправлено:** добавлен `webContents.on('will-navigate', ...)`, уводящий такие переходы в `shell.openExternal`.

### 1.5. Вотчер не фильтровал события внутри игнорируемых директорий
`isIgnored(path.basename(filename))` проверял только последний сегмент — событие вида `node_modules/foo/index.js` не игнорировалось, `.gitignore` в вотчере не применялся вовсе. Во время `npm install` внутри воркспейса это давало шторм пересборок дерева и запросов `git status`.

**Исправлено:** проверяются все сегменты пути + применяется тот же `ignore`-инстанс, что и в `buildFileTree`. Заодно устранена утечка памяти в `recentSelfWrites` (см. 2.6).

## 2. Баги средней важности — ✅ исправлены

- **2.1 Гонка в `openTab` → дубликаты вкладок** — дедупликация перенесена внутрь функционального `setTabs` апдейтера.
- **2.2 В GlobalSearch не работал Enter** — добавлена навигация стрелками, Enter открывает выбранный результат, устаревшие ответы поиска отменяются.
- **2.3 Double-Shift: ложные срабатывания и невыполненное «закрыть»** — двойной Shift теперь считается только если между нажатиями не было других клавиш (не путает с CamelCase-набором), и переключает (открывает/закрывает), а не только открывает.
- **2.4 Завершившийся шелл оставлял «мёртвую» вкладку терминала** — `Terminal` теперь получает `onExit`, вкладка закрывается сама.
- **2.5 Файл, открытый через «Open With» при холодном старте, мог не открыться** — main больше не шлёт файл до готовности renderer'а; renderer явно сообщает о готовности (`renderer-ready`), только после этого очередь открытий разбирается.
- **2.6 Утечка памяти в `recentSelfWrites`** — записи чистятся по таймеру (ограничено ~10 сек), а не растут неограниченно.
- **2.7 Диалоги: параллельный запрос «подвешивал» предыдущий Promise** — в `dialogs.ts` теперь очередь вместо одного слота.
- **2.8 Синхронный поиск по всем проектам блокировал main-процесс** — переписан на `fs.promises` (каждый вызов уступает event loop), с честным лимитом на файл и на общий счётчик результатов.
- **2.9 Shell-инъекция в «Run Python»** — путь экранируется (`lib/shellQuote.ts`) перед вставкой в команду терминала.
- **2.10 Терминал: неверный фолбэк шелла** — `/bin/zsh` → `/bin/bash` для Linux, `process.env.HOME` → `os.homedir()`.

## 4. Windows: разделители путей — ⏸ сознательно не применялось

Была подготовлена нормализация путей (`lib/path.ts` + правки в ~10 файлах renderer'а, плюс `execFile`/`python` фиксы в `lint.ts` под Windows), но **откачена по решению пользователя**: в CI (`.github/workflows/build.yml`) сейчас собирается только `macos-latest` (windows/ubuntu отключены), а без реальной Windows-машины эти правки нельзя было проверить. Если Windows-таргет когда-нибудь снова понадобится — вернуться к этому разделу; сама проблема (renderer предполагает `/` как разделитель, main отдаёт нативные пути) при этом никуда не делась.

## 6. Рефакторинг / чистота кода — ✅ применено

1. Дублирование `UI_MODES` (`shared/settings.ts` и `density.ts`) — оставлен один источник (`shared/settings.ts`).
2. `useTerminals.closeTerminal` — side effect внутри апдейтера `setTerminals` убран; `activeTermId`/`showTerminal` теперь derived-значения, вычисляемые из `terminals` при рендере, без лишнего прохода рендера.
3. Пустые `catch (e) {}` в main (`git.ts`, `settings.ts`, `recentExternalFiles.ts`, `workspaces.ts`) — добавлен `console.warn` с контекстом там, где ошибка не является ожидаемой (не тронуты «горячие» пути и уже документированные намеренно-тихие блоки).
4. `build:mac` в package.json унифицирован с `build:win`/`build:linux` (`npm run build &&` вместо прямого `electron-vite build &&`).

Не тронуто (осталось как есть, не влияет на корректность): разбиение `App.tsx`/`Sidebar.tsx` на более мелкие компоненты, кэш `.gitignore` только в корне воркспейса, дублирование типизации IPC между `main/index.ts`/`preload/*` — эти пункты остаются в бэклоге, если решите взяться за более глубокий рефакторинг.

## 7. Размер mac-сборки — ✅ исправлено: 398 МБ → 304 МБ

| | До | После |
|---|---|---|
| `AuraPad.app` (весь) | 398 МБ | **304 МБ** |
| `app.asar` | 120 МБ | **27 МБ** |
| `.dmg` | 135 МБ | **128 МБ** |

Что сделано:
1. Renderer-зависимости (`monaco-editor`, `@monaco-editor/react`, `lucide-react`, `@xterm/*`, `marked`, `dompurify`, `clsx`, `tailwind-merge`) перенесены в `devDependencies` — Vite всё равно бандлит их в `out/renderer`, а electron-builder перестал класть их исходники в asar по второму разу.
2. Из asar исключены `docs/`, `.claude/`, `.idea/`, `.github/`, конфиги tailwind/postcss, `tsconfig.node.tsbuildinfo`, `AUDIT.md`, а также собственные source/build-скрипты `node-pty` (`src/deps/third_party/scripts` — только скомпилированный аддон нужен в рантайме).
3. **Важный нюанс, найденный в процессе:** electron-builder уже сам по умолчанию исключает `.pdb`-отладочные символы (это оказалось ~28 из ~30 МБ «лишнего» веса каждой платформы `node-pty/prebuilds/*`) — ручная попытка вырезать чужие платформенные prebuild-бинарники через **вложенные `files:` под `mac:`/`win:`/`linux:`** сломала default-исключения electron-builder (`.git`, папка сборки) и раздула asar до 323 МБ. Урок: **не используйте platform-specific `files:` в electron-builder.yml, если top-level `files:` уже состоит только из `!`-исключений** — это ломает его внутреннюю логику вставки дефолтных паттернов. Все прежние top-level исключения (п. 1-2 выше) работают корректно и без этой ловушки.
4. `274 МБ Electron Framework` — не убрать, это цена самого Electron.
